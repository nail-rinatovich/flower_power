# Flower Power

Магазин цветов на Django 5.2: каталог с категориями, поиском и сортировкой, страницы товаров, корзина в сессии и русская админка. Адаптивный интерфейс для телефона и компьютера.

## Запуск в Windows

Нужен Python 3.10 или новее. Если команда `python` запускает старую версию, используйте полный путь к актуальному Python.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_shop
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000 --noreload
```

Сайт: http://127.0.0.1:8000/ · Админка: http://127.0.0.1:8000/admin/

После первоначальной настройки можно запускать через `powershell -ExecutionPolicy Bypass -File .\start.ps1`.

## Управление товарами

Войдите в админку под созданным суперпользователем. В разделе «Категории» добавьте категории, затем в разделе «Товары» — товары. Укажите название, уникальный адрес (заполняется автоматически), категорию, описание и цену. Можно загрузить фотографию, добавить состав букета и метку. Поле «В продаже» управляет видимостью товара. Загруженные фотографии сохраняются в `media/` и имеют приоритет над ссылками.

Команда `seed_shop` добавляет 8 демонстрационных товаров и не перезаписывает существующие. Демо-фотографии загружаются с Unsplash; при отсутствии сети показывается локальная иллюстрация. Для реального каталога загрузите собственные фотографии через админку. Оформление использует системные шрифты и не ждёт загрузки Google Fonts.

## Корзина

Для добавления товаров регистрация не нужна. Корзина сохраняется в браузерной сессии на 14 дней, цена пересчитывается из базы при просмотре. Количество от 1 до 99, ноль удаляет товар. Недоступные и удалённые товары исключаются автоматически. Вход администратора не нужен покупателям.

Оформление заказа, оплата и доставка не подключены. Проект реализует каталог и корзину; кнопок фиктивной оплаты нет.

## Деплой на Render Free с SQLite

`render.yaml` создаёт **бесплатный Python Web Service**, без PostgreSQL и постоянного диска. Shell и SSH не нужны: миграции, создание администратора и загрузка демо-каталога выполняются автоматически при старте.

**Это демонстрационный вариант.** На Render Free SQLite, добавленные товары, сессии и загруженные фотографии могут теряться после перезапуска, деплоя или остановки бесплатного экземпляра. Администратор и демо-букеты создаются заново из настроек запуска. Бесплатный сервис также засыпает при отсутствии запросов, поэтому первое открытие после простоя занимает время. Для постоянного реального каталога потребуется постоянное хранилище или другой тариф.

1. Откройте [Render Dashboard](https://dashboard.render.com/), выберите **New → Blueprint**, подключите `nail-rinatovich/flower_power`, ветку `main`.
2. Проверьте тариф **Free**. Render попросит значение `DJANGO_SUPERUSER_PASSWORD`: задайте сильный уникальный пароль. Не используйте локальный пароль `124`. Сохраните пароль у себя; в GitHub он не попадёт.
3. Создайте Blueprint и дождитесь **Live**. Админка доступна по `/admin/`, логин по умолчанию — `admin`, почта не нужна. Пароль — тот, который вы ввели в Render.
4. После запуска можете управлять товарами в админке. Изменения сохраняются только в течение жизни текущей файловой системы бесплатного экземпляра.

При сборке `build.sh` устанавливает зависимости, собирает статику и проверяет production-настройки. При запуске `start.sh` выполняет миграции, команду `bootstrap_admin`, при `SEED_DEMO_DATA=1` — `seed_shop`, затем запускает Gunicorn. Инициализация повторяется безопасно: существующие товары и пароль действующего администратора не перезаписываются. Обычный пользователь с совпавшим именем автоматически не становится администратором.

Сгенерированный Render секрет содержит 256 случайных бит в Base64. На Render приложение преобразует такой ключ в стабильную 64-символьную hex-запись с той же случайностью, чтобы пройти проверку длины Django. Слабые или вручную заданные короткие ключи этим преобразованием не маскируются и по-прежнему блокируют сборку.

Если хотите отключить демо-букеты, задайте `SEED_DEMO_DATA=0`. Тогда на новой базе каталог будет пустым. При значении `1` удалённые демо-букеты могут появляться заново при запуске.

### Ручное создание Web Service вместо Blueprint

Выберите runtime **Python 3**, build command `bash build.sh`, start command `bash start.sh`, health check `/healthz/` и тариф **Free**. Диск не подключайте. В разделе **Environment** задайте:

| Переменная | Значение |
| --- | --- |
| `DJANGO_DEBUG` | `0` |
| `DJANGO_SECRET_KEY` | Длинная случайная строка; Blueprint генерирует её автоматически |
| `DJANGO_SUPERUSER_USERNAME` | `admin` или выбранный вами логин |
| `DJANGO_SUPERUSER_PASSWORD` | Сильный уникальный пароль; хранить только в Render |
| `SEED_DEMO_DATA` | `1` для демо-каталога или `0` для пустого каталога |

Удалите прежние переменные `DJANGO_DB_PATH=/var/data/db.sqlite3` и `DJANGO_MEDIA_ROOT=/var/data/media`, если они уже были настроены: на Free такого диска нет. По умолчанию база `db.sqlite3` и каталог `media/` находятся в папке приложения. Настройка `DJANGO_DB_PATH` остаётся доступной для других вариантов размещения.

Домен `RENDER_EXTERNAL_HOSTNAME` добавляется в разрешённые хосты и CSRF origins автоматически. Для своего домена задайте `DJANGO_ALLOWED_HOSTS=example.com,www.example.com` и `DJANGO_CSRF_TRUSTED_ORIGINS=https://example.com,https://www.example.com`.

Если в базе уже есть администратор, изменение `DJANGO_SUPERUSER_PASSWORD` само по себе не меняет его пароль. Для новой пустой базы используется текущее значение переменной. Не храните пароль в репозитории или командах сборки.

Локальная база, фотографии и пароли в GitHub не загружаются. Bash-скрипты предназначены для Render Linux; локальный Windows-запуск через `start.ps1` не создаёт администратора автоматически.

Справка: [ограничения Render Free](https://render.com/docs/free), [Django на Render](https://render.com/docs/deploy-django).
