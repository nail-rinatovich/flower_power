# Flower Power

Магазин цветов на Django 5.2: каталог с категориями, поиском и сортировкой, страницы товаров, корзина в сессии и русская админка. Адаптивный интерфейс для телефона и компьютера.

## Запуск в Windows

Нужен Python 3.10 или новее. Если команда `python` запускает старую версию, используйте полный путь к актуальному Python.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_shop
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000 --noreload
```

Сайт: http://127.0.0.1:8000/ · Админка: http://127.0.0.1:8000/admin/

После первоначальной настройки можно запускать через `powershell -ExecutionPolicy Bypass -File .\start.ps1`.

## Управление товарами

Войдите в админку под созданным суперпользователем. В разделе «Категории» добавьте категории, затем в разделе «Товары» — товары. Укажите название, уникальный адрес (заполняется автоматически), категорию, описание и цену. Можно загрузить фотографию, добавить состав букета и метку. Поле «В продаже» управляет видимостью товара. Загруженные фотографии сохраняются в `media/` и имеют приоритет над ссылками.

Команда `seed_shop` добавляет 8 демонстрационных товаров и не перезаписывает существующие. Демо-фотографии загружаются с Unsplash; при отсутствии сети показывается локальная иллюстрация. Для реального каталога загрузите собственные фотографии через админку. Оформление использует системные шрифты и не ждёт загрузки Google Fonts.

## Корзина

Для добавления товаров регистрация не нужна. Корзина сохраняется в браузерной сессии на 14 дней, цена пересчитывается из базы при просмотре. Количество от 1 до 99, ноль удаляет товар. Недоступные и удалённые товары исключаются автоматически. Вход администратора не нужен покупателям.

Оформление заказа, оплата и доставка не подключены. Проект реализует каталог и корзину; кнопок фиктивной оплаты нет.

## Деплой на Render.com с SQLite

В репозитории есть `render.yaml` (Blueprint). Он создаёт Python Web Service на тарифе **0.5c-512mb (512 МБ)** с **платным постоянным диском 1 ГБ**. PostgreSQL и внешнее хранилище не нужны. Проверьте стоимость ресурсов в Render перед созданием. Бесплатный веб-сервис не поддерживает постоянный диск: без диска SQLite и загруженные фотографии теряются при перезапуске или деплое.

1. Откройте [Render Dashboard](https://dashboard.render.com/), выберите **New → Blueprint** и подключите репозиторий `nail-rinatovich/flower_power`, ветку `main`.
2. Render прочитает `render.yaml`. Проверьте сервис `flower-power`, тариф 0.5c-512mb и диск `/var/data`, затем создайте Blueprint.
3. Дождитесь статуса **Live**. Адрес сервиса будет показан в Render, админка доступна по `/admin/`.
4. Откройте **Shell** веб-сервиса и создайте администратора: `python manage.py createsuperuser`. Почту можно оставить пустой. Для публичного сайта задайте новый сильный пароль; локальный администратор автоматически не переносится.
5. При необходимости добавьте демонстрационный каталог: `python manage.py seed_shop`. Либо добавьте свои категории и товары в админке.

При создании Blueprint Render генерирует секрет и задаёт переменные окружения. База хранится в `/var/data/db.sqlite3`, фотографии — в `/var/data/media`. Миграции выполняются при каждом запуске, после подключения диска. Один процесс Gunicorn с четырьмя потоками обслуживает сайт; для SQLite настроено ожидание блокировки до 20 секунд. Несколько экземпляров приложения с одной такой базой не поддерживаются.

`build.sh` устанавливает зависимости, собирает статику WhiteNoise и проверяет production-настройки. `start.sh` выполняет миграции и запускает Gunicorn. Скрипты Bash предназначены для Linux на Render; локально Windows использует `start.ps1`. Фотографии отдаются приложением только для файлов, указанных у товаров; произвольные файлы диска недоступны. Для большого количества изображений и нагрузки потребуется отдельное файловое хранилище.

### Ручное создание Web Service вместо Blueprint

Выберите runtime **Python 3**, build command `bash build.sh`, start command `bash start.sh`, health check `/healthz/`, тариф 0.5c-512mb. Прикрепите диск 1 ГБ к `/var/data` и задайте:

| Переменная | Значение |
| --- | --- |
| `DJANGO_DEBUG` | `0` |
| `DJANGO_SECRET_KEY` | Длинная случайная строка, хранится только в Render |
| `DJANGO_DB_PATH` | `/var/data/db.sqlite3` |
| `DJANGO_MEDIA_ROOT` | `/var/data/media` |

Домен `RENDER_EXTERNAL_HOSTNAME` автоматически добавляется в разрешённые хосты и CSRF origins. Для собственного домена дополнительно задайте `DJANGO_ALLOWED_HOSTS=example.com,www.example.com` и `DJANGO_CSRF_TRUSTED_ORIGINS=https://example.com,https://www.example.com`.

### Данные и резервные копии

Локальная `db.sqlite3`, фотографии, сессии и пароли **не отправляются в GitHub**. Новый Render-сервис начинает с новой базы; если требуется перенести существующий каталог, сделайте отдельный экспорт и импорт. Не заменяйте рабочую базу при последующих деплоях. Сохраняйте резервные копии SQLite через SQLite backup API и копии `/var/data/media`; простой перенос открытого файла базы может дать несогласованную копию.

Справка: [Django на Render](https://render.com/docs/deploy-django), [постоянные диски](https://render.com/docs/disks).
